# Topic Intelligence 对外文案规范

官网、README、Plugin 展示和安装页统一表达用户价值，不展示内部架构、验收过程、发布阻塞或路线图。

## 核心定位

**从当前热点中找到值得研究的题，再把一个题材变成清晰、可执行的内容简报。**

## 三种用法

- 选题：比较当前信号、新鲜度和来源覆盖，给出少量候选；
- 简报：把给定题材整理成角度、结构、核验项和素材建议；
- 选题加简报：选出一个题材，并继续为同一题材生成简报。

## Radar 入口文案

标题：

> 安装 Topic Intelligence Skill，快速获取热点选题

说明：

> 把当前 Radar 信号交给你的 Agent，筛选值得研究的题材，并生成角度、核验清单和素材建议。

步骤提示：

> 获取 Skill → 安装启用 → 发起选题

按钮：

> 获取 Skill

按钮进入 Topic Intelligence Skill 的介绍和获取页；不得使用“开始研究”“立即生成”等会让用户误以为点击后直接执行 Skill 的文案。

## Skill 介绍页文案

标题：

> 安装一个 Skill，让 Agent 帮你从热点找到选题

说明：

> Topic Intelligence Skill 读取当前 Radar 信号，帮你筛选值得研究的题材，并把同一题材整理成研究型内容简报。

主按钮：

> 获取 Skill

次按钮：

主按钮进入最新正式 Release，不把 Release 页面写成直接下载，不固定已经过期的版本号；次按钮定位到当前页面的安装方法，不把用户带回上一步的 Radar。

## 证据边界

- 当前信号元数据和来源链接来自公开 Radar，但不等于对外部主张的独立核验；
- 来源不完整或数据较旧时明确说明；
- 不把模型记忆或旧快照冒充当前证据；
- 不承诺受众规模、内容饱和度、未来传播量或“爆款”。
- 重要主张进入 `must_verify`，优先回到一手来源核验。

## 不在用户页面展示

- Smoke、Host Eval、raw trace 和内部 PASS 标记；
- 发布前置条件、审核阻塞和候选包状态；
- 内部命令、接口编排、配额实现和未来 Premium 方案；
- 开发路线图、实验指标和历史迁移说明。

以上内容需要保留时，应放在测试、架构、运维或发布证据文档中。

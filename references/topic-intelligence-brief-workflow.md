# Topic Intelligence brief workflow

Use this reference only when the request asks for an evidence-backed content
brief, research plan, angle, hook, verification plan, or production handoff.

## Resolve one topic

- Supplied current topic: preserve its exact `id`; do not run a selection feed.
- Select then brief: run one bounded feed, choose one finalist, and never run a
  second feed.
- Topic name without stable identity: run at most one bounded `feed --q
  <supplied-topic-name>` solely to resolve the same topic. Accept only a clear
  semantic match, preserve the resolved `id`, and never substitute another topic.
- History is optional and finalist-only.

If the supplied ID lacks enough current topic facts, or a supplied name has no
clear current match, ask for the current card or state the evidence gap. Do not
reselect a different topic as a convenience.

## Build with host reasoning

Use the host model to create the editorial plan from the Radar observations.
Adapt depth to the user's requested format. A research-ready brief normally
contains:

- topic title and stable Radar ID;
- freshness, stage, score, evidence breadth, and source limitations;
- recommendation, audience payoff, why now, and one angle;
- hook/opening and narrative beats;
- research questions, search queries, and preferred source types;
- `must_verify`, `avoid_claims`, unknowns, and risks;
- factual visual requirements and optional illustrative material.

Keep Radar observations, host analysis, and recommendations visibly distinct. Radar does
not measure actual audience size, topic/content saturation, or future virality.
China-market fit, audience breadth, and distribution potential are editorial
judgments unless a current field directly establishes the claim.
